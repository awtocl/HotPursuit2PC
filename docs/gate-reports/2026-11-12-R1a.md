## 2. Verified

- `pwsh tools/build.ps1` and `-Preset release`: **12 CTest tests pass** in both (two new: `test_recomp` on a
  hand-assembled program, `test_recomp_dump` on the owner's executable).
- `hp2recomp check-trace` on the traced session exits with 0: every executed instruction decodes; **0 of 29,860**
  executed blocks start anywhere the analysis had not predicted; no game code ran outside `.text`; `.text` was not
  modified in memory; none of the executed code was "orphan".
- All 431,681 words of `.text` decode; 10,146 functions; 193 switches with 3,077 cases; the only 3 unrecognised
  indirect jumps are in the C++ exception unwinder.
- All 125 vector-unit blocks that ran are in the executable's `.vutext` (`tools/recon/vucheck.py`).
- Time shares of a busy race refresh, three runs: total 13.3–15.0 ms; game program 5.6–6.1; vector unit 4.1–5.8;
  VIF + GIF 2.2–2.8; sound + I/O 0.7. Compilation: ≈ 0.2 ms per block, 29,935 blocks in the session.
- Pacer fix: emulated-refresh intervals more than 25 % off went from 48.4 % to 1.4 % in the videos and from 23.0 %
  to 2.6 % in the menus; the race is unchanged (`docs/evidence/m1-acceptance.md` §4b).
- The example game folder `.cache/m1-run/game` was updated with the fixed launcher by re-running the converter
  (the previous launcher was kept aside as a `.mismatch-N` file).

## 3. Not verified

- Anything beyond one 82-second scripted session: 58 % of the code did not run; other modes, tracks, replays.
- That every return goes back to its call site (the block list has no order). The translator's lock-step run will
  test it.
- The meaning of instructions: the decoder identifies them; no semantics are implemented yet.
- Whether the pacer defect was part of the sound problem the owner heard; whether the fix is audible or visible to
  the owner. All measurement runs were muted.
- LLVM: its license text, size, build time and whether it builds here are estimates from prior knowledge.
- The expected gain of the recompiled code (ADR 0007's "≤ 3 ms") is a target, not a measurement.
- The GitHub Actions workflow has still never run (nothing is pushed).

## 6. Plan for the next phase (R1b)

With a yes: fetch and build LLVM (license recorded first) → add execution counters to the tracing executor to
find the hot functions → translate about 20 of them and one microprogram → run them in lock-step with the core's
JIT and time them in isolation → accept or rewrite ADR 0007 → whole-program translation as a converter stage.
In parallel and in either case: an interpreter on top of the decoder as the semantic ground truth, and traces of
more sessions.
